# دار الطفل المسلم — نسخة مستقلة

نسخة مستخرجة من الإصدار 12، commit `602759b80b7840c4eb1a39094b881b457e15ab34` بتاريخ 29 سبتمبر 2026. تشمل كود التطبيق والشعارات والواجهات وكل ترحيلات قاعدة البيانات؛ **لا تشمل بيانات المستخدمين أو الصور المرفوعة من الموقع الحالي**. أدوات تصدير واستيراد هذه البيانات مرفقة.

أصبحت النسخة تعمل بـ **Next.js 16.3.4 + React 19 على Node.js 24** بدل تشغيل Vinext داخل Cloudflare Workers. استُبدلت D1 بـ SQLite على قرص السيرفر، وR2 بمجلد خاص للصور والمرفقات. الحسابات والأدوار وعمليات المراجعة والحضور والمرتبات محفوظة. لا تحتاج ChatGPT لتسجيل الدخول أو للتشغيل.

هذه الحزمة معدة لسيرفر واحد بقرص دائم؛ لا تشغّل عدة نسخ تتشارك SQLite عبر شبكة. ليست رفع HTML إلى public_html ولا تعمل على استضافة PHP فقط. تحتاج Node.js 24 أو Docker. راجع DEPLOYMENT.md قبل النشر.

## تشغيل محلي — Windows / Linux / macOS

ثبّت Node.js 24، وافتح Terminal داخل المجلد:

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
```

انسخ `.env.example` إلى `.env` من مدير الملفات. اترك `APP_ORIGIN=http://localhost:3000` للتشغيل المحلي. البيانات في `data/`.

**لو ستنقل البيانات الحالية: نفّذ قسم النقل أدناه قبل إنشاء إدارة جديدة.**

لبداية جديدة، اكتب كلمة مرور قوية في `ADMIN_PASSWORD` داخل `.env` الخاص بك، ثم:

```sh
npm run db:migrate
npm run admin:create
```

اكتب الاسم والهاتف بكود الدولة `+20...` حين يطلبهما الأمر. احذف `ADMIN_PASSWORD` من `.env` بعد الإنشاء. لا يوجد حساب افتراضي أو كلمة مرور افتراضية، وإنشاء الإدارة عبر الويب مغلق.

```sh
npm run build
npm start
```

افتح http://localhost:3000 ثم بوابة الإدارة، وسجّل بالهاتف وكلمة المرور. دخول HTTP مسموح محليًا فقط؛ النشر العام يحتاج HTTPS. للتطوير: شغّل `npm run db:migrate` ثم `node --env-file=.env node_modules/next/dist/bin/next dev --webpack`.

## نقل البيانات الحالية بالكامل

1. اتفق مع الإدارة على وقف إدخال بيانات جديدة مؤقتًا في الموقع القديم وقت النقل؛ التصدير ليس لقطة ذرية أثناء تعديلات متزامنة.
2. داخل `.env` الخاص بك فقط أضف:

```dotenv
SOURCE_URL=https://dar-al-tifl-al-muslim.ahmedelgezawy1133.chatgpt.site
SOURCE_PHONE=رقم_أو_اسم_مستخدم_الإدارة
SOURCE_PASSWORD=كلمة_مرور_الإدارة
```

3. شغّل محليًا:

```sh
npm run data:export
```

ينزّل `backups/migration-export/snapshot.json` وكل الصور والإيصالات بأسمائها الأصلية في `media/`. يفشل إذا ملف ناقص، ولا يكتب snapshot النجاح إلا بعد تنزيل كل المرفقات. يعمل فقط بحساب إدارة صالح. لا ترسل كلمات المرور في المحادثة. احذف SOURCE_PASSWORD بعد التصدير.

4. على قاعدة جديدة فارغة، **قبل إنشاء أي إدارة**:

```sh
npm run data:import -- backups/migration-export/snapshot.json backups/migration-export/media
```

تُحفظ كلمات مرور المستخدمين، ويُطلب تسجيل الدخول مجددًا. يمكن استيراد النسخة المشفرة من صفحة الإعدادات أيضًا بوضع `BACKUP_PASSPHRASE` في `.env`، مع توفير مجلد كل المرفقات؛ النسخة المشفرة وحدها لا تحتوي الصور. امسح عبارة فك التشفير بعد النقل.

5. جرّب حساب الإدارة والشيخ والطالب وولي الأمر، وقارن أعداد الحسابات والطلاب والحلقات والسجلات والمرفقات قبل فتح التسجيل على السيرفر الجديد. لا توقف الموقع القديم نهائيًا قبل التحقق.

## الملفات والنسخ الاحتياطي

- `data/academy.sqlite`: قاعدة البيانات، ومعها ملفات WAL/SHM أثناء التشغيل.
- `data/uploads/`: صور وإيصالات خاصة، لا تضعه تحت public ولا تقدم ملفات منه مباشرة عبر nginx.
- `public/`: الشعارات والأصول العامة.
- `drizzle/0000...0006`: ترحيلات SQL الأصلية، تُطبّق مرة واحدة داخل معاملات مع التحقق من بصمتها.
- `runtime/`: SQLite والتخزين وإعدادات الأمان.
- `deployment/nginx.conf`: جزء إعدادات الوكيل العكسي.

للنسخ الاحتياطي المتسق: أوقف التطبيق، ثم انسخ مجلد `data` بالكامل إلى مكان خاص خارج السيرفر، ثم أعد التشغيل. في Docker استخدم إجراء DEPLOYMENT.md لحفظ volume كاملًا. لا تنسخ SQLite وحده أثناء تشغيله. اختبر الاسترجاع دوريًا. الحذف العرضي للقرص أو volume يحذف البيانات؛ الملفات الدائمة تحتاج نسخًا خارجية.

## إعدادات البيئة

| المتغير | الاستخدام |
|---|---|
| APP_ORIGIN | عنوان الموقع النهائي، مثال https://dar.example.com؛ مطلوب ولا يضم مسارًا |
| DATA_DIR | مسار دائم للبيانات؛ محليًا ./data، وداخل Docker /app/data |
| PORT / BIND_HOST | منفذ وعنوان الربط عند npm start؛ الافتراضي 3000 و127.0.0.1 |
| TRUST_PROXY | 1 فقط خلف nginx الذي يستبدل X-Real-IP مع منع الوصول المباشر للتطبيق |
| ADMIN_PASSWORD | مؤقت لإنشاء الإدارة الجديدة؛ احذفه بعد الإنشاء |
| BACKUP_PASSPHRASE | مؤقت لاستيراد نسخة مشفرة |
| SOURCE_URL / SOURCE_PHONE / SOURCE_PASSWORD | مؤقت لتصدير الموقع القديم |
| TWILIO_ACCOUNT_SID / TWILIO_AUTH_TOKEN / TWILIO_VERIFY_SERVICE_SID | اختياري لتفعيل تأكيد الهاتف |
| OTP_CHANNEL | sms أو whatsapp حسب خدمة Verify المفعّلة |

بدون Twilio يظل التسجيل العادي متاحًا، ويُمنع اشتراك الحسابات الجديدة في رقم واحد. لا توجد أكواد وهمية. لا يتغير اعتماد الشيخ أو الإدارة بعد التحقق من الهاتف. استقبال الرسائل الحقيقية لم يُختبر دون بيانات خدمة فعالة.

لا ترفع إلى GitHub: `.env`، كلمات المرور أو رموز الخدمات، `data/`، `backups/`، صور المستخدمين، نسخ قواعد البيانات، `node_modules/` أو `.next/`. `.env.example` فقط آمن للنشر بقيمه الفارغة.
